- 시스템 관리자
- 개발/유지보수 담당자

## 3. 세부 프로세스 분석

### 3.1 프로세스 P01: 간호사 등록/관리

#### 프로세스 정의
| 항목 | 내용 |
|------|------|
| 프로세스 ID | P01 |
| 프로세스명 | 간호사 등록/관리 |
| 담당자 | 수간호사 |
| 선행 조건 | 병동이 시스템에 등록되어 있을 것 |
| 후행 프로세스 | P02 (근무표 생성) |

#### 프로세스 흐름

```
[시작] → 간호사 관리 메뉴 이동
         │
         ├─→ [신규 등록]
         │      │
         │      ▼
         │    사원번호·사원명·직위·정렬순서 입력
         │      │
         │      ▼
         │    유효성 검증 (사원번호 중복 확인)
         │      │
         │      ├─→ 실패: 오류 메시지 표시
         │      └─→ 성공: DB 저장 → 목록 갱신
         │
         ├─→ [수정]
         │      │
         │      ▼
         │    기존 정보 로드 → 수정 → 저장
         │
         └─→ [삭제 (퇴직처리)]
                │
                ▼
              employmentStatus → "RESIGNED"
              (물리 삭제 아닌 논리 삭제)
```

#### 데이터 흐름

| 단계 | 입력 | 처리 | 출력 |
|------|------|------|------|
| 등록 | 사원번호, 사원명, 직위(HN/CN/AN/RN), 정렬순서, 팀 | POST `/api/nurses` → Prisma create | Nurse 레코드 생성 |
| 수정 | 변경된 필드 | PUT `/api/nurses/[id]` → Prisma update | Nurse 레코드 갱신 |
| 삭제 | nurseId | DELETE `/api/nurses/[id]` → status 변경 | employmentStatus = "RESIGNED" |
| 조회 | wardId, status 필터 | GET `/api/nurses` → Prisma findMany | Nurse 목록 (sortOrder 순) |

#### 비즈니스 규칙
- 사원번호는 시스템 전체에서 고유해야 함
- 직위 코드: HN(수간호사, rank 1), CN(책임간호사, rank 2), AN(주임간호사, rank 3), RN(일반간호사, rank 4)
- 정렬순서(sortOrder)로 근무표 내 표시 순서를 결정
- 퇴직 처리된 간호사는 새 근무표에 표시되지 않음
- 기존 근무표에 배정된 간호사의 이력은 보존

### 3.2 프로세스 P02: 근무표 생성

#### 프로세스 정의
| 항목 | 내용 |
|------|------|
| 프로세스 ID | P02 |
| 프로세스명 | 월간 근무표 생성 |
| 담당자 | 수간호사 |
| 선행 조건 | P01 완료 (간호사 등록) |
| 후행 프로세스 | P03 (근무 입력/편집) |

#### 프로세스 흐름

```
[시작] → 근무표 관리 메뉴 이동
         │
         ▼
       [새 근무표] 클릭
         │
         ▼
       연도/월 선택 다이얼로그
         │
         ▼
       POST /api/schedules
         │
         ├─→ 해당 ward+year+month의 다음 version 자동 계산
         │
         ├─→ Schedule 레코드 생성 (status: DRAFT)
         │
         └─→ 생성된 근무표 편집 페이지로 이동
                │
                ▼
              초기 로드 시 처리:
                │
                ├─→ 기존 엔트리가 있으면: DB에서 로드
                │
                └─→ 엔트리 없으면 (신규):
                      │
                      ▼
                    병동 소속 간호사 자동 배정
                      │
                      ├─→ HN/CN: 평일=D, 주말=O 자동 채움
                      └─→ AN/RN: 빈 상태
```

#### 데이터 흐름

| 단계 | 입력 | 처리 | 출력 |
|------|------|------|------|
| 생성 | wardId, year, month | POST `/api/schedules` | Schedule 레코드 (DRAFT) |
| 초기 로드 | scheduleId | GET `/api/schedules/[id]` + entries | gridData (Zustand 저장) |
| 자동 배정 | 간호사 목록, 해당 월 달력 | 클라이언트에서 계산 | HN/CN의 entries 프리셋 |

#### 비즈니스 규칙
- 같은 병동+연도+월에 여러 버전 생성 가능 (version 자동 증가)
- 생성 시 status는 항상 DRAFT
- 수간호사(HN)와 책임간호사(CN)는 평일 주간근무(D), 주말 공휴(O)로 자동 채움
- 주임간호사(AN)와 일반간호사(RN)는 빈 상태로 시작

### 3.3 프로세스 P03: 근무 입력/편집

#### 프로세스 정의
| 항목 | 내용 |
|------|------|
| 프로세스 ID | P03 |
| 프로세스명 | 근무표 입력/편집 |
| 담당자 | 수간호사 |
| 선행 조건 | P02 완료 (근무표 생성), 근무표 status = DRAFT |
| 후행 프로세스 | P04 (저장), P05 (확정) |

#### 프로세스 흐름

```
[시작] → 근무표 편집 페이지 진입
         │
         ▼
       그리드 로드 (ScheduleGrid)
         │
         ├─→ 좌측 고정 컬럼: 사원번호, 사원명, 직위
         ├─→ 중앙: 1일~말일 셀 (근무코드)
         ├─→ 우측: 집계 (D/E/N/T/X/O/X+O) + 통계 (주말/연속/시간)
         └─→ 하단: 일별 근무 집계 (D/E/N/T/X, T+X, 총인원)
         │
         ▼
       셀 편집 (4가지 방법)
         │
         ├─→ (a) 클릭 입력
         │      셀 클릭 → ShiftCell 팝업 → 근무코드 선택 (D/E/N/O/X/T/B)
         │
         ├─→ (b) 드래그 선택
         │      마우스 드래그 → 범위 선택 → 근무코드 일괄 적용
         │
         ├─→ (c) Shift + 클릭
         │      시작 셀 클릭 → Shift + 끝 셀 → 범위 확장
         │
         └─→ (d) Ctrl+C / Ctrl+V (Hidden Textarea 패턴, Google Sheets 방식)
                복사: 선택 범위 → hidden textarea에 탭 구분 텍스트 → Ctrl+C로 클립보드
                붙여넣기: Ctrl+V → hidden textarea의 paste 이벤트 → 파싱 → 유효한 근무코드만 적용
                외부 붙여넣기: 엑셀/메모장에서 복사한 탭 구분 데이터도 그리드에 직접 붙여넣기 가능
         │
         ▼
       Zustand Store 업데이트
         │
         ├─→ updateCell() / updateCells()
         ├─→ summary 자동 재계산 (D/E/N/T/X/O/XO)
         ├─→ isDirty = true (미저장 변경 플래그)
         └─→ UI 즉시 반영 (memo 최적화)
```

#### 부가 기능

```
       ┌─────────────────────────────┐
       │     부가 편집 기능           │
       │                             │
       │  [사원 추가]                │
       │    → 미배정 간호사 선택      │
       │    → gridData에 행 추가     │
       │                             │
       │  [사원 제거]                │
       │    → 행 우측 X 버튼 클릭    │
       │    → gridData에서 행 제거   │
       │                             │
       │  [이전 월 불러오기]          │
       │    → 전월 확정 근무표 참조   │
       │    → 이전 집계 정보 표시    │
       │                             │
       │  [초기화]                   │
       │    → 전체 셀 빈 상태로      │
       │    → 확인 다이얼로그 표시   │
       └─────────────────────────────┘
```

#### 데이터 흐름

| 단계 | 입력 | 처리 | 출력 |
|------|------|------|------|
| 셀 편집 | nurseId, day, shiftCode | Zustand updateCell() | gridData 갱신, summary 재계산 |
| 범위 붙여넣기 | 클립보드 텍스트 (TSV) | Zustand updateCells() | 다수 셀 일괄 갱신 |
| 사원 추가 | nurseId | Zustand addNurse() | gridData에 행 추가 |
| 사원 제거 | nurseId | Zustand removeNurse() | gridData에서 행 제거 |
| 이전 월 참조 | scheduleId | GET `/api/schedules/[id]/previous` | 전월 집계 데이터 |

#### 비즈니스 규칙
- 유효한 근무코드: D, E, N, O, X, T, M, CS2, C6, C, B (빈 값도 허용)
- 확정(CONFIRMED) 상태에서는 편집 불가 (editable=false)
- 셀 편집 시 집계 자동 재계산: D, E, N, T, X, O 카운트 + XO = X+O
- 추가 통계: 주말근무 횟수, 최대연속근무일, 총근무시간 (8시간/근무)
- 일별 집계 footer: D/E/N/T/X 각 합계, T+X 합계, 일별 총인원

### 3.4 프로세스 P04: 근무표 저장

#### 프로세스 정의
| 항목 | 내용 |
|------|------|
| 프로세스 ID | P04 |
| 프로세스명 | 근무표 저장 |
| 담당자 | 수간호사 |
| 선행 조건 | P03에서 셀 편집 완료 (isDirty = true) |
| 후행 프로세스 | P05 (확정) 또는 P03 (추가 편집) |

#### 프로세스 흐름

```
[시작] → [저장] 버튼 클릭
         │
         ▼
       isDirty 확인
         │
         ├─→ false: 저장할 변경사항 없음 (스킵)
         │
         └─→ true: 저장 프로세스 시작
                │
                ▼
              gridData에서 entries 추출
                │
                ▼
              PUT /api/schedules/[id]/entries
              { entries: [...], nurseIds: [...] }
                │
                ▼
              서버 처리 (트랜잭션):
                │
                ├─ 1. 기존 DB 엔트리 조회
                │
                ├─ 2. 변경 감지 (diff)
                │     ├─ 신규 엔트리 → INSERT
                │     ├─ 변경된 엔트리 → UPDATE
                │     └─ 삭제된 엔트리 → DELETE
                │
                ├─ 3. 변경마다 ScheduleChangeLog 생성
                │     (previousShiftCode, newShiftCode, version)
                │
                ├─ 4. ScheduleEntry upsert
                │
                ├─ 5. 영향받은 간호사의 ScheduleSummary 재계산
                │
                └─ 6. nurseIds에 없는 간호사의 Summary 정리
                │
                ▼
              isDirty = false
              성공 메시지 표시
```

#### 데이터 흐름

| 단계 | 입력 | 처리 | 출력 |
|------|------|------|------|
| 전송 | gridData.entries + nurseIds | PUT API | - |
| 변경 감지 | 기존 DB entries vs 새 entries | diff 비교 | 변경/추가/삭제 목록 |
| 이력 기록 | 각 변경건 | ScheduleChangeLog 생성 | 감사 이력 |
| 엔트리 저장 | entries | Prisma upsert/delete | ScheduleEntry 갱신 |
| 집계 갱신 | 영향받은 nurseId 목록 | count 재계산 | ScheduleSummary 갱신 |

#### 비즈니스 규칙
- 저장은 전체 엔트리가 아닌 **변경분만** 처리 (성능 최적화)
- 모든 변경은 ScheduleChangeLog에 기록 (감사 추적)
- 변경 이력에는 변경 전/후 근무코드, 버전 정보 포함
- nurseIds로 근무표에서 제거된 간호사의 집계 데이터도 정리

### 3.5 프로세스 P05: 근무표 확정/확정취소

#### 프로세스 정의
| 항목 | 내용 |
|------|------|
| 프로세스 ID | P05 |
| 프로세스명 | 근무표 확정 및 확정취소 |
| 담당자 | 수간호사 |
| 선행 조건 | P04 완료 (저장 완료, isDirty = false) |
| 후행 프로세스 | P06 (대시보드 반영), P07 (출력) |

#### 확정 프로세스 흐름

```
[시작] → [확정] 버튼 클릭
         │
         ▼
       확정 전 검증:
         │
         ├─→ ① isDirty 확인 → 미저장 변경 있으면 저장 먼저 요청
         │
         ├─→ ② 빈 셀 확인 → 모든 간호사의 모든 날짜에 근무코드 필요
         │     └─→ 빈 셀 있으면: "모든 간호사의 모든 날짜에 근무가 입력되어야 합니다" 오류
         │
         └─→ ③ 확인 다이얼로그 표시
                │
                ▼
              PATCH /api/schedules/[id] { status: "CONFIRMED" }
                │
                ▼
              서버 검증:
                │
                ├─→ 같은 ward+year+month에 이미 CONFIRMED가 있는지 확인
                │     └─→ 있으면: "이미 확정된 근무표가 있습니다" 오류
                │
                └─→ 없으면: status → CONFIRMED, confirmedAt 기록
                │
                ▼
              확정 완료
                │
                ├─→ 편집 기능 비활성화 (editable = false)
                ├─→ [저장], [초기화], [사원 추가/제거] 잠김
                └─→ 대시보드에 반영
```

#### 확정취소 프로세스 흐름

```
[시작] → [확정 취소] 버튼 클릭
         │
         ▼
       확인 다이얼로그 표시
         │
         ▼
       PATCH /api/schedules/[id] { status: "DRAFT" }
         │
         ▼
       status → DRAFT, confirmedAt/confirmedBy 초기화
         │
         ▼
       편집 기능 재활성화
```

#### 비즈니스 규칙
- **확정 전 필수 조건**: 저장 완료 (isDirty=false) + 모든 셀 입력 완료
- **1개월 1확정**: 같은 병동+연도+월에 CONFIRMED 상태는 1개만 허용
- **확정 후 잠김**: 셀 편집, 저장, 초기화, 사원 추가/제거 모두 비활성화
- **확정 취소**: CONFIRMED → DRAFT로 되돌리면 다시 편집 가능
- **대시보드 연동**: 대시보드는 CONFIRMED 상태의 근무표만 표시

### 3.6 프로세스 P06: 대시보드 조회

#### 프로세스 정의
| 항목 | 내용 |
|------|------|
| 프로세스 ID | P06 |
| 프로세스명 | 대시보드 조회 |
| 담당자 | 수간호사 / 책임간호사 |
| 선행 조건 | P05 완료 (확정된 근무표 존재) |
| 트리거 | 대시보드 페이지 접근 시 자동 실행 |

#### 프로세스 흐름

```
[시작] → 대시보드 페이지 접근 (Server Component)
         │
         ▼
       당월 CONFIRMED 근무표 조회 (Prisma 직접 쿼리)
         │
         ├─→ 확정 근무표 없음 → "확정된 근무표가 없습니다" 표시
         │
         └─→ 확정 근무표 있음:
                │
                ├─→ ① 금일 근무현황
                │     오늘 날짜의 간호사별 근무코드 추출
                │     D/E/N/O/X별 간호사 목록 그룹핑
                │
                ├─→ ② 주간 미리보기
                │     이번 주(월~일) 전체 간호사 근무 표시
                │
                ├─→ ③ 공정성 지표
                │     간호사별 D/E/N/O/X 횟수 분포
                │     편차 계산 (최대-최소)
                │
                ├─→ ④ 알림 (경고)
                │     ├─ 연속 근무 5일 이상 감지
                │     └─ N→D 연속 배치 감지 (야간 후 주간)
                │
                └─→ ⑤ 인력 현황
                      직위별 간호사 수
                      근무 중 / 휴무 인원 통계
                │
                ▼
              SSR HTML 렌더링 → 클라이언트 전송
```

#### 비즈니스 규칙
- Server Component로 구현 → 클라이언트 JS 최소화, 빠른 초기 로드
- CONFIRMED 상태의 근무표만 대시보드에 표시
- 연속 근무 경고: 근무코드 D/E/N/T/B 중 5일 연속 이상
- N→D 경고: 야간(N) 다음 날 주간(D) 배치 감지
- `force-dynamic` 설정으로 Vercel 캐싱 비활성화 (항상 최신 데이터)

### 3.7 프로세스 P07: 출력 (엑셀/인쇄)

#### 프로세스 정의
| 항목 | 내용 |
|------|------|
| 프로세스 ID | P07 |
| 프로세스명 | 근무표 출력 |
| 담당자 | 수간호사 |
| 선행 조건 | P04 완료 (저장 완료) |
| 트리거 | [엑셀 다운로드] 또는 [인쇄] 버튼 클릭 |

#### 엑셀 다운로드 흐름

```
[시작] → [엑셀 다운로드] 클릭
         │
         ▼
       GET /api/schedules/[id]/excel
         │
         ▼
       서버 처리:
         │
         ├─→ Schedule + Entries + Nurses 조회
         ├─→ SheetJS로 워크시트 생성
         │     ├─ 헤더: 사원번호, 사원명, 직위, 1일~말일, 집계
         │     ├─ 본문: 간호사별 근무코드
         │     └─ 하단: 일별 집계 (D/E/N/T/X, T+X, 총인원)
         └─→ .xlsx 바이너리 응답
         │
         ▼
       브라우저 파일 다운로드
       파일명: "{연도}년_{월}월_{병동명}_근무확정표_v{버전}.xlsx"
```

#### 인쇄 흐름

```
[시작] → [인쇄] 클릭
         │
         ▼
       react-to-print 실행
         │
         ▼
       PrintLayout 컴포넌트 렌더링
         │
         ├─→ 인쇄 전용 HTML 테이블
         │     ├─ 근무표 헤더 (병동, 연월, 버전)
         │     ├─ 간호사별 근무 그리드
         │     ├─ 집계 행
         │     └─ 일별 근무 집계
         │
         └─→ 브라우저 인쇄 다이얼로그
         │
         ▼
       인쇄 완료 → POST /api/schedules/[id]/print
       (인쇄 이력 기록: 인쇄자, 일시, 형식)
```

#### 비즈니스 규칙
- 엑셀 파일은 기존 엑셀 양식과 동일한 형태로 생성
- 인쇄 레이아웃은 PrintLayout 컴포넌트에서 별도 관리
- 인쇄 이력은 SchedulePrintLog에 자동 기록

## 6. 예외 처리

### 6.1 오류 시나리오 및 대응

| 시나리오 | 원인 | 시스템 대응 | 사용자 안내 |
|----------|------|-----------|------------|
| 저장 실패 | 네트워크 오류, DB 접속 실패 | API 에러 응답 (500) | "저장 실패" 메시지 + 재시도 유도 |
| 확정 실패 - 빈 셀 | 미입력 근무코드 존재 | API 에러 응답 (400) | "모든 간호사의 모든 날짜에 근무가 입력되어야 합니다" |
| 확정 실패 - 중복 | 동일 월 다른 버전 이미 확정 | API 에러 응답 (409) | "이미 확정된 근무표가 있습니다" |
| 확정 실패 - 미저장 | isDirty = true | 클라이언트 검증 | "저장되지 않은 변경사항이 있습니다" |
| 사원번호 중복 | 이미 존재하는 사원번호 | API 에러 응답 (400) | "이미 사용 중인 사원번호입니다" |
| 삭제 실패 | 근무표에 배정된 간호사 | 논리 삭제 (퇴직처리) | "퇴직 처리되었습니다" |

### 6.2 동시성 처리
- 현재 낙관적 잠금 미구현 (단일 사용자 환경 가정)
- 저장 시 전체 entries 비교로 충돌 감지 가능
- 향후 version 필드 기반 낙관적 잠금 도입 가능
