## 1. 기술 요약

본 시스템은 Next.js 14와 Spring Boot 3.2를 기반으로 하는 병동 간호사 근무표 관리 애플리케이션으로, PostgreSQL 16과 Redis 7.2를 조합하여 데이터 영속성과 캐싱 성능을 확보하며, Spring Security 6과 JWT를 통해 인증 및 권한 관리를 수행합니다.

아키텍처는 프레젠테이션, 비즈니스 로직, 데이터 액세스로 분리된 3계층 레이어드 구조를 채택하여 각 계층의 독립적 유지보수와 확장이 가능합니다. 특히 Spring State Machine 기반의 승인 워크플로우 엔진을 내장하여 근무표 편성부터 최종 확정까지의 다단계 승인 프로세스를 체계적으로 관리하며, Hibernate Envers를 통한 감사 이력 추적으로 모든 변경 사항의 투명한 기록을 보장합니다.

핵심 기술 결정으로 Java 17과 TypeScript 5.3 등 타입 안전성이 높은 언어를 선택하여 대규모 스케줄 데이터 처리 시 런타임 오류를 최소화했습니다. 또한 Redis 캐싱 레이어와 API Gateway를 도입하여 반복적인 근무표 조회 및 집계 요청의 응답 속도를 개선하고 보안 정책을 일원화했습니다.

예상되는 기술 리스크로는 복잡한 교대근무 규칙 적용 시 워크플로우 엔진의 상태 관리 복잡도 증가와 동시 편집 충돌이 있으며, 이에 대비하여 상태 전이 규칙의 단위 테스트 자동화와 낙관적 잠금 기반의 동시성 제어 전략을 적용할 계획입니다.

## 3. 시스템 아키텍처

### 3.1 아키텍처 개요

Spring Boot 기반의 3계층 아키텍처로 설계된 병동 간호사 근무표 관리 시스템입니다. 프론트엔드(Next.js)와 백엔드(Spring Boot)를 명확히 분리하고, Spring State Machine을 통한 승인 워크플로우와 Hibernate Envers를 통한 감사 이력을 핵심으로 구성합니다. Redis 캐싱과 API Gateway를 통해 성능과 보안을 최적화하며, 근무표 자동 집계 및 출력 기능을 제공합니다.

**아키텍처 스타일**: Layered Architecture with Workflow Engine and Audit Trail

### 3.2 아키텍처 레이어

#### Presentation Layer
사용자 인터페이스, 근무표 편집/조회, 인쇄 기능을 담당

| 컴포넌트 | 타입 | 설명 |
|----------|------|------|
| Web Application | frontend | Next.js 14 기반 SSR/CSR 하이브리드 애플리케이션. TanStack Table로 근무표 그리드를 렌더링하고 Zustand로 클라이언트 상태를 관리 |

#### Gateway Layer
API 라우팅, 인증 필터링, 요청 제한을 담당하는 진입점

| 컴포넌트 | 타입 | 설명 |
|----------|------|------|
| API Gateway | gateway | Spring Cloud Gateway 4.1 기반 API 게이트웨이. JWT 검증, 요청 라우팅, Rate Limiting 처리 |

#### Application Layer
핵심 비즈니스 로직, 워크플로우 처리, 인증/인가를 담당

| 컴포넌트 | 타입 | 설명 |
|----------|------|------|
| Auth Service | backend | Spring Security 6 기반 인증/인가 서비스. JWT 발급, RBAC 권한 관리 |
| Schedule Service | backend | 근무표 CRUD, 자동 집계, 유효성 검증을 담당하는 핵심 비즈니스 서비스 |
| Workflow Service | backend | Spring State Machine 4.0 기반 근무표 확정/승인 워크플로우 엔진 |
| Audit Service | backend | Hibernate Envers 6.4 기반 수정 이력 추적 및 감사 로그 서비스 |
| Staff Service | backend | 간호사 사원 정보, 직위, 병동 배치를 관리하는 서비스 |
| Report Service | backend | Apache POI 5.2 및 iText 8 기반 근무표 문서 생성 및 출력 서비스 |

#### Data Layer
영구 데이터 저장, 캐싱, 감사 이력 저장을 담당

| 컴포넌트 | 타입 | 설명 |
|----------|------|------|
| Primary Database | database | PostgreSQL 16 - 사용자, 근무표, 스케줄, 워크플로우, 감사 이력 등 모든 영구 데이터 저장. Spring Data JPA를 통해 접근 |
| Session Cache | cache | Redis 7.2 - JWT 블랙리스트, 세션 데이터, 리프레시 토큰 저장 |
| Data Cache | cache | Redis 7.2 - 근무표 조회 캐싱, 집계 결과 캐싱, 임시 데이터 저장 |

#### Infrastructure Layer
컨테이너 오케스트레이션, 리버스 프록시, CI/CD를 담당

| 컴포넌트 | 타입 | 설명 |
|----------|------|------|
| Reverse Proxy | infrastructure | Nginx 1.25 - 리버스 프록시, 정적 파일 서빙, SSL 종단, 로드 밸런싱 |
| Container Orchestration | infrastructure | Docker 25 + Docker Compose 2.24 - 전체 서비스 컨테이너화 및 오케스트레이션 |
| CI/CD Pipeline | infrastructure | GitHub Actions 기반 지속적 통합/배포 파이프라인 |

### 3.3 데이터 흐름

1) 인증 흐름: 사용자 로그인 → Nginx → API Gateway (JWT 발급 요청) → Auth Service → PostgreSQL (사용자 검증) → Redis (세션/토큰 저장) → JWT 토큰 반환 → 클라이언트 저장. 2) 근무표 조회 흐름: 클라이언트 요청 → Nginx → API Gateway (JWT 검증) → Schedule Service → Redis 캐시 확인 → 캐시 미스 시 PostgreSQL 조회 → 근무 유형별 자동 집계 수행 → Redis 캐시 저장 → TanStack Table 그리드에 렌더링. 3) 근무표 수정 흐름: 수간호사 근무 변경 → API Gateway → Schedule Service (유효성 검증) → PostgreSQL 업데이트 → Hibernate Envers 자동 이력 기록 (_AUD 테이블) → Redis 캐시 무효화 → 변경 결과 반환. 4) 승인 워크플로우 흐름: 수간호사 근무표 제출 → Workflow Service (State Machine: DRAFT → SUBMITTED) → 승인권자에게 알림 → 승인권자 검토/승인 → State Machine (SUBMITTED → APPROVED → CONFIRMED) → 각 상태 전이마다 PostgreSQL 이력 기록. 5) 리포트 출력 흐름: 인쇄 요청 → Report Service → Schedule Service (데이터 조회) → Apache POI (Excel) 또는 iText (PDF) 문서 생성 → 파일 다운로드 응답 / React-to-Print를 통한 브라우저 직접 인쇄. 6) 사원 관리 흐름: 관리자 간호사 정보 등록/수정 → API Gateway → Staff Service → PostgreSQL (사원 정보 저장) → Redis 캐시 갱신.

## 4. 데이터베이스 설계

**데이터베이스 유형**: RDBMS
**권장 엔진**: PostgreSQL 15

### 4.1 엔티티 정의

#### wards
병동 정보를 관리하는 테이블. 42병동 등 병원 내 간호 단위 구분

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- ward_code: VARCHAR(20) UNIQUE NOT NULL
- ward_name: VARCHAR(100) NOT NULL
- description: TEXT
- is_active: BOOLEAN DEFAULT true
- created_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
- updated_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- 1:N nurses (병동 소속 간호사)
- 1:N schedules (병동별 월간 근무표)

#### nurses
간호사 사원 정보 테이블. 사원번호, 사원명, 직위 및 소속 병동 관리 (REQ-006)

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- employee_number: VARCHAR(20) UNIQUE NOT NULL
- name: VARCHAR(100) NOT NULL
- position: VARCHAR(50) NOT NULL
- position_rank: INTEGER NOT NULL DEFAULT 0
- ward_id: UUID NOT NULL REFERENCES wards(id)
- employment_status: VARCHAR(20) NOT NULL DEFAULT 'ACTIVE' CHECK (employment_status IN ('ACTIVE', 'LEAVE', 'RESIGNED'))
- hire_date: DATE
- sort_order: INTEGER DEFAULT 0
- created_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
- updated_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- N:1 wards
- 1:N schedule_entries (간호사별 근무 배정)

#### users
시스템 사용자 계정 테이블. 수간호사, 간호과장, 간호부장 등 근무표 작성/승인 권한자 관리

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- login_id: VARCHAR(100) UNIQUE NOT NULL
- password_hash: VARCHAR(255) NOT NULL
- name: VARCHAR(100) NOT NULL
- role: VARCHAR(30) NOT NULL CHECK (role IN ('HEAD_NURSE', 'NURSING_MANAGER', 'NURSING_DIRECTOR', 'ADMIN'))
- nurse_id: UUID REFERENCES nurses(id)
- ward_id: UUID REFERENCES wards(id)
- is_active: BOOLEAN DEFAULT true
- last_login_at: TIMESTAMP WITH TIME ZONE
- created_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
- updated_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- N:1 nurses (선택적, 간호사 겸직 시)
- N:1 wards (선택적, 병동 담당자)
- 1:N schedules (근무표 작성자)
- 1:N schedule_approvals (승인 처리자)
- 1:N schedule_change_logs (수정 이력 작성자)
- 1:N schedule_print_logs (출력 이력)

#### shift_types
근무 유형 마스터 테이블. D(Day), E(Evening), N(Night), T, X(휴무), O(Off), X+O 등 근무 코드 정의

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- code: VARCHAR(10) UNIQUE NOT NULL
- name: VARCHAR(50) NOT NULL
- description: VARCHAR(200)
- color_code: VARCHAR(7)
- is_working_day: BOOLEAN NOT NULL DEFAULT true
- display_order: INTEGER DEFAULT 0
- is_active: BOOLEAN DEFAULT true
- created_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- 1:N schedule_entries (근무 배정에서 참조)

#### schedules
월간 근무확정표 헤더 테이블. 병동별/연월별 근무표 단위를 관리하며 확정 상태 및 버전을 추적 (REQ-001, REQ-003, REQ-005)

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- ward_id: UUID NOT NULL REFERENCES wards(id)
- year: INTEGER NOT NULL
- month: INTEGER NOT NULL CHECK (month BETWEEN 1 AND 12)
- version: INTEGER NOT NULL DEFAULT 1
- status: VARCHAR(20) NOT NULL DEFAULT 'DRAFT' CHECK (status IN ('DRAFT', 'PENDING_MANAGER', 'PENDING_DIRECTOR', 'APPROVED', 'CONFIRMED', 'REVISED'))
- created_by: UUID NOT NULL REFERENCES users(id)
- confirmed_at: TIMESTAMP WITH TIME ZONE
- confirmed_by: UUID REFERENCES users(id)
- notes: TEXT
- created_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
- updated_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- N:1 wards
- N:1 users (created_by)
- N:1 users (confirmed_by)
- 1:N schedule_entries (일별 근무 배정)
- 1:N schedule_approvals (승인 이력)
- 1:N schedule_change_logs (수정 이력)
- 1:N schedule_print_logs (출력 이력)

#### schedule_entries
근무표 상세 엔트리 테이블. 간호사별/일별 근무 유형을 저장하는 핵심 데이터 테이블 (REQ-001, REQ-002)

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- schedule_id: UUID NOT NULL REFERENCES schedules(id) ON DELETE CASCADE
- nurse_id: UUID NOT NULL REFERENCES nurses(id)
- work_date: DATE NOT NULL
- shift_type_code: VARCHAR(10) NOT NULL REFERENCES shift_types(code)
- is_modified: BOOLEAN DEFAULT false
- created_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
- updated_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- N:1 schedules
- N:1 nurses
- N:1 shift_types (via shift_type_code)

#### schedule_summaries
간호사별 월간 근무 유형 집계 테이블. 근무 유형별 횟수를 비정규화하여 저장 (REQ-002 성능 최적화, 선택적 비정규화)

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- schedule_id: UUID NOT NULL REFERENCES schedules(id) ON DELETE CASCADE
- nurse_id: UUID NOT NULL REFERENCES nurses(id)
- count_d: INTEGER NOT NULL DEFAULT 0
- count_e: INTEGER NOT NULL DEFAULT 0
- count_n: INTEGER NOT NULL DEFAULT 0
- count_t: INTEGER NOT NULL DEFAULT 0
- count_x: INTEGER NOT NULL DEFAULT 0
- count_o: INTEGER NOT NULL DEFAULT 0
- count_xo: INTEGER NOT NULL DEFAULT 0
- total_working_days: INTEGER NOT NULL DEFAULT 0
- total_off_days: INTEGER NOT NULL DEFAULT 0
- created_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
- updated_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- N:1 schedules
- N:1 nurses

#### schedule_approvals
근무표 승인 워크플로우 이력 테이블. 수간호사→간호과장→간호부장 단계별 승인 과정 기록 (REQ-003)

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- schedule_id: UUID NOT NULL REFERENCES schedules(id) ON DELETE CASCADE
- approval_step: INTEGER NOT NULL CHECK (approval_step BETWEEN 1 AND 3)
- approval_role: VARCHAR(30) NOT NULL CHECK (approval_role IN ('HEAD_NURSE', 'NURSING_MANAGER', 'NURSING_DIRECTOR'))
- approver_id: UUID NOT NULL REFERENCES users(id)
- action: VARCHAR(20) NOT NULL CHECK (action IN ('SUBMIT', 'APPROVE', 'REJECT', 'RETURN'))
- comment: TEXT
- acted_at: TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP

**기본 키**: id

**관계**:
- N:1 schedules
- N:1 users (approver)

#### schedule_change_logs
근무표 수정 이력 테이블. 확정 후 수정 시 변경 전/후 값을 셀 단위로 기록하여 변경 추적 (REQ-004)

**속성**:
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- schedule_id: UUID NOT NULL REFERENCES schedules(id) ON DELETE CASCADE
- nurse_id: UUID NOT NULL REFERENCES nurses(id)
- work_date: DATE NOT NULL
- previous_shift_code: VARCHAR(10) REFERENCES shift_types(code)
